# 更新日志 / Changelog

这里保留已记录的版本历史。历史条目描述当时的实现，不代表当前操作方式；当前用法请参阅 README。

## 0.1.11 多耳机控制与路由恢复（开发预览）

- 使用统一的输出阶段机管理设备切换、媒体与提示音确认、聚合资源释放；区分用户勾选与实际生效成员。
- 改善 AirPods 摘戴、HAL 句柄更换和成员暂时离线时的路由恢复；其余已选设备继续播放，保留原勾选，有恢复证据后重新加入。
- 多副可控耳机上下排列，分别控制连接、噪声模式和停止控制，不再手动选择唯一控制对象。
- 保持切设备时 APP 列表的位置、音量和静音配置，复用电平发布源；实时电平不冻结旧数据。
- 重复选择同一路由不再重建音频图；过渡期间保留仍在目标路由中的已验证空闲耳机连接，撤销命令授权，减少不必要的蓝牙重扫。
- 新增 GitHub Release 更新检查、下载进度、SHA-256 校验和退出后的更新安装 helper；更新需要用户确认。
- 调整面板、滚动和操作按钮布局，补充中英文界面与路由、耳机、更新流程的回归测试。
- 增加音频切换操作的耗时区间，便于后续实测 HAL 重配与 APP 会话重建。

### 已知问题

- AirPods 聆听模式仍可能返回 HAL 写入拒绝；本版只改进拒写后的状态处理，尚未彻底解决模式切换兼容性。
- 尚未实现无缝输出交接，切换仍可能短暂停顿；伴随的网络卡顿尚未定位。
- 开发预览安装包为 Apple Silicon 架构、本地 ad-hoc 签名，未完成 Apple 公证。

## 0.1.10 路由稳定与后台效率

- 新增独立设置窗口、中英文界面，以及跟随系统、浅色和深色外观。
- 耳机控制和多设备输出入口默认关闭，可在设置中显示。
- 新增开机启动开关，使用 macOS 登录项服务，首次运行不主动注册。
- 多设备输出使用单一可展开入口，支持一台设备；勾选直接应用，并提供成员音量控制。
- 调整菜单、深色悬停和设置分组布局。
- 修正输出切换的状态确认与失败时的勾选显示；AirPods 取消勾选后的实际播放仍待实机验收。
- 监听系统默认媒体与提示音输出变化，蓝牙抢回路由时立即恢复用户保留的设备。
- 释放多输出设备后重新读取 HAL 设备列表，设备未真正消失时保留清理入口。
- 隐藏面板且没有已管理应用时，周期刷新只读取输出路由；完整进程与输入设备扫描在打开面板或需要管理时执行，避免后台空转。
- 相同状态不再重复触发 SwiftUI 发布与排版，隐藏面板空闲 CPU 从周期性高占用降至约 1% 以内。

### 0.1.1 实机反馈修复

修正短 RPC 响应：明确解析 5 字节（8 位错误码）与上游测试记录的 6 字节（LE16 错误码）格式。保留其他长度错误的严格拒绝，并显示帧类型、预期长度与实际长度。协议诊断最多保留最近 24 条，每条接收数据最多显示 64 字节，只在本机内存与界面存在；分享前请自行检查内容。

### 0.1.2 应用音量可用性修正

修正旧版在组装列表前过滤所有 `isRunningOutput == 0` 进程，导致播放器暂停时整块空白的问题。普通应用身份来自 NSWorkspace，注册音频对象来自 Core Audio，播放活跃只作为状态，不再作为列表存在条件。

滑杆/静音配置、管理意图、已启动会话、失败锁存分别建模；无音频对象就明确等待，有对象后才创建 tap。首次处理从零淡入所设增益，避免先输出 100% 再调低。权限不足、输出不支持、资源释放失败等错误不会被其他捕获方式替代。

只读应用诊断：

```sh
./dist/Aural.app/Contents/MacOS/Aural --diagnose-applications
```

报告包含真实运行 App、归属的音频进程、对象 ID 和活跃标记。它不启动捕获、不申请录制权限，也不提供未经验证的“已授权”结论；分享前请自行检查本地应用身份信息。

### 0.1.3 界面精简

主界面仅保留输出、音量、应用与耳机操作，移除标语、开发标识、统计和常驻说明。待应用配置及真实错误仍保留；正常运行状态放在悬停提示中。顶栏只保留一个更多菜单；版本、打开控制窗口、立即刷新、音频录制权限入口与“复制耳机诊断”均收在其中。只调整表现层，不改变音频和耳机协议逻辑。

### 0.1.4 只显示播放中的应用

根据用户明确要求，界面仅展示 `isRunningOutput == true` 的应用。后台归属目录与展示列表分开，不能因隐藏暂停行而停止管理或重置配置；恢复播放后重新显示。当前使用系统音频输出活动标记，不用是否运行、是否注册、是否受管理来代替播放条件。只读 `--diagnose-applications` 仍报告完整后台目录，不能把它的总行数当成界面可见行数。

### 0.1.5 耳机自动识别

当前系统默认输出为 Px7 S3 时，包括启动时已连接的耳机，自动发现并建立本地控制通道。已验证的输出 UID→BLE UUID 绑定跨 Aural 重启保留；没有绑定时收集至少 2 秒广播，仅自动选名称规范化后完全相同的唯一候选，不按信号强弱挑选，不猜泛化广播。首次需要手动确认时，选一次、读取成功后即可记住。

- 音乐设备的配对/音频连接仍由 macOS 负责，Aural 不替你切换系统输出。
- 主动“断开/取消”会抑制本次音频连接期间的自动连接；切走输出再切回或明确点连接可恢复。
- 意外 BLE 断连按 2/5/10 秒最多重连 3 次；RPC 拒绝、解码错误、扫描超时、权限拒绝不会无限重试。
- 休眠停止扫描和控制，唤醒后根据真实输出恢复。没有恢复降噪/透传预设，也没有自动发出 SET。
- 右上角耳机选项的“重新选择耳机”是明确的手动身份更新，不是自动失败后猜别的设备。

显式硬件验收命令（会扫描蓝牙、连接控制、只读电量与降噪，退出前断开；不要与另一份 Aural 或耳机控制工具同时运行）：

```sh
./dist/Aural.app/Contents/MacOS/Aural --diagnose-headphones
```

退出码：0=真实读取确认；2=需要首次选择；1=失败/超时。该诊断与正常 App 共用控制器和绑定，不创建第二个 AppModel、不发设置命令。


### 0.1.6 应用识别修正

- 通过进程父子关系和可执行文件路径，将音频辅助进程归到所属应用，补全 AppKit 未登记的进程信息。
- 排除 Aural、FineTune 及系统内部音频服务；无法确认宿主的来源只显示可核实的真实进程名，不猜测应用名称。
- 系统输出暂时读取失败时，保留用户主动断开和连接失败记录，避免恢复读取后立即误触发重连。
- 应用只读诊断增加原始音频进程、归属信息及读取错误；耳机诊断增加独占检查，避免与运行中的 Aural 同时连接耳机。

### 0.1.7 耳机驱动与身份验证

- 复用 HeadBridge 的 B&W PX/PI 家族识别、Sony MDR V1 和 OPPO Enco 协议与传输；保留第三方来源和 MIT 许可。
- 修正旧 BLE UUID 绑定导致耳机停在选择阶段的问题。发现唯一候选后自动连接，并核对耳机硬件地址与当前系统输出；身份不匹配时明确报错，不改连其他候选。
- 传输中断采用有次数限制的重连；权限拒绝、身份不匹配和协议错误不会被自动绕过。
- 界面显示真实设备名、电量及已确认的噪声模式；修改模式后等待耳机回读确认，不提前显示成功。

本版接入驱动不等于完成所有型号的实机验证，Sony/OPPO 未经本机硬件验收。不支持 Sony V2，未知 OPPO 型号不启用降噪写入。

### 0.1.8 单行实时电平

面板默认 440pt 宽，与 Magpie 的标准面板宽度一致，采用浅灰平铺列表。各内容页独立测量；主动切页时按目标页高度调整外框，停留期间的异步状态和新内容通过内部滚动展示，隐藏耳机页不会撑高 APP 页。菜单栏使用固定锚点的自持有浮层，不通过 NSPopover 逐帧重定位。浮层直接显示和收起，不使用弹出、缩放或淡入动画，也不绘制顶部箭头；只有主动切页保留内容和高度过渡；内容淡入淡出只作用于透明度，不把动画事务传给滚动容器或控件布局，窗口高度仅由 AppKit 插值，避免双重布局动画造成上下抖动。选中块使用 0.14 秒、外框通过 AppKit 原生 animator 使用 0.24 秒无回弹缓出（不再自行逐帧 setFrame），快速反向切换从当前高度继续；系统启用减少动态效果时直接切换。原生滚动容器不显示横竖拖动条，但保留滚轮和触控板滚动。顶部使用“输出 / 麦克风 / 耳机控制”三个同级页签，不再保留二级设备切换。输出页列出全部输出设备，分别读取和控制硬件音量与静音；只有点击设备名称才切换默认输出。未公开硬件属性的设备明确显示不支持，不切换其他后端、不填入默认音量。麦克风页列出系统输入设备，可切换默认麦克风、调节输入音量与硬件静音，不采集或录制输入音频，不提供未经实现的按 APP 麦克风增益。输出页与麦克风页下方保留相同的 APP 播放音量区；耳机页只保留耳机功能，不重复展示设备音量或 APP 列表。应用行按“电平、图标、名称、静音、滑杆、百分比”排列，重试与停止管理移到右键菜单，不保留三个点。电平表为 10×20pt，音量条采用细轨道，支持键盘与辅助功能调整。峰值用 -60…0 dBFS 对数刻度，不是系统音量或扬声器声压；已管理时位于 Aural 增益/静音之后。自动只读计量只在应用音量面板可见、对应 App 正在播放且没有失败时启用，仍需系统音频录制权限；不写文件或上传。实时回调仅计算峰值并写预分配原子邮箱，界面以 30Hz 消费并平滑回落。错误保留为同行图标、悬停与菜单，计量失败可以单独重试，不能借重试电平擅自启用音量管理。


### 0.1.9 首次权限

蓝牙授权通过 CoreBluetooth 管理器触发；系统音频没有独立的公开授权查询/申请函数，使用一个私有、unmuted、无物理输出的短生命周期 tap 输入触发系统申请后立即释放。回调忽略全部输入，不保存或重放音频，也不改变现有输出或音量。不使用私有 TCC 或屏幕录制授权替代这项权限；已有决定不强制重置。正常主模型在申请入口执行且探测资源已释放后才构造；探测资源清理失败只报告错误并退出，不继续留着采集输入运行；只读命令行诊断不执行该流程。蓝牙关闭且尚未发生决定时不阻塞启动，下次启动仍可申请。用户可以拒绝；调用成功和本地首次标记都不构成已授权证明。

Apple 要求保留用途说明：[蓝牙](https://developer.apple.com/documentation/bundleresources/information-property-list/nsbluetoothalwaysusagedescription)、[系统音频与 tap](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps)。当前分别为“用于控制蓝牙耳机。”和“用于调节应用音量。”。
